# Solution: The service with no destinations

`VW-I001` · Author guidance; independently unreviewed.

## Evidence and conclusion

The supplied mismatch is sufficient to explain why the Service has no selected endpoints. Ready Pods are excluded by release=r7. The evidence supports a selection failure; it does not independently establish gateway health.

## Plausible alternatives

NetworkPolicy, wrong targetPort and application listener failures can break traffic even after endpoints appear. Distinguish them using endpoint addresses, listening port evidence and a bounded request from an authorised client.

## Recovery verification

After reviewing rollout intent, align the selector or restore the intended stable Pods. Verify ready EndpointSlices and repeated requests through the user route. If using a real cluster, save the prior Service manifest and use a lab namespace only.

## Prevention and trade-offs

Keep stable routing labels separate from release identity unless version routing is intentional. A selector test prevents this class of error but cannot test application correctness.
