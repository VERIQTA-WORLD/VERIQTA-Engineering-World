# AI curriculum plan

This plan organises the AI learning area into 15 sections. These are planned learning units, not a claim that the full curriculum is available. Existing activities are linked from the [AI index](README.md); each section will be filled and reviewed as part of the selected folder’s development.

The first three sections establish boundaries and evaluation before tool-specific assistance. Tool sections additionally require the corresponding engineering fundamentals. Retrieval precedes tool calling; project development follows both evaluation and permission design.

| Order | Section | Existing material to develop or missing work | Completion evidence |
| --- | --- | --- | --- |
| AI-01 | Capabilities, limitations and suitable engineering uses | Expand the AI index into explanations and contrasting cases | Choose assistance versus deterministic automation; identify unsupported certainty |
| AI-02 | Context preparation, prompting and structured outputs | New sanitisation and schema fixtures | Minimise input, preserve relevant context and reject malformed outputs |
| AI-03 | Verification and evaluation | Connect existing mock-response exercises with a shared case rubric | Reject fluent false answers; distinguish mock mechanics from observed model performance |
| AI-04 | Linux and system administration | Deepen VW-A001: storage, processes, service evidence | Verify scope and command effects; resist injected instructions in logs |
| AI-05 | Networking and cloud | Deepen VW-A002; add DNS/routing/TLS evidence cases | Ground each claim in supplied evidence and official policy/protocol semantics |
| AI-06 | Git, Bash and Python | New diff/conflict and automation boundary cases | Preserve requirements; test spaces, missing input, types and failure handling |
| AI-07 | Docker and container workflows | Deepen VW-A003 with context, layers and runtime cases | Detect layer-persistence mistakes and verify suggested changes locally |
| AI-08 | Jenkins, GitHub Actions and GitLab CI/CD | New pipeline evidence and security-context cases | Explain why a fix works without expanding authority or masking failure |
| AI-09 | Terraform and Ansible | VW-A005 reserved; add convergence/check-mode cases | Compare plan actions and first/second-run evidence before accepting recommendations |
| AI-10 | Kubernetes, Helm and Argo CD | Deepen VW-A004; split into manifests/events, probes/scheduling, service diagnosis, and render/sync subsections | Verify each diagnosis using manifests, events, logs and endpoints; avoid fictional root cause |
| AI-11 | Prometheus, Grafana and OpenTelemetry | New query/alert, dashboard-gap and trace-context cases | Test missing-series behavior and source provenance; identify missing instrumentation |
| AI-12 | Security, incident response and SRE | New permission-diff, incident timeline and recovery-option cases | Preserve sensitive-data boundaries, distinguish facts from hypotheses and retain human decisions |
| AI-13 | Retrieval and knowledge freshness | Develop VW-P002's retrieval component into guided practice | Cite actual approved passages, handle stale/irrelevant/no-match sources and traversal attempts |
| AI-14 | Tool calling and controlled agents | New bounded read-only tools and audit fixtures | Demonstrate authority limits, approval boundaries, timeout/failure handling and no arbitrary execution |
| AI-15 | Practical AI engineering projects | Deepen VW-P002; add configuration reviewer after its prerequisite sections | Case-level groundedness, boundary, fallback, latency/token/cost records; real-model use optional |

Every tool-specific AI section needs representative sanitised input, an interaction, a convincing incorrect response, independent verification, complete solutions and an explicit engineer-owned decision. Keep paid calls optional. Split a section further if its promised scope prevents thorough treatment.
