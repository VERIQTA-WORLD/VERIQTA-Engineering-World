# Solution: Review a CI gate before giving it authority

`VW-E003` · Solution and reasoning

## Review findings

`pull_request_target` can run in the base repository security context. This fixture checks out attacker-controlled head code, then executes its script. `write-all` expands authority, and `|| true` hides failure. Use a normal PR event with read-only permissions, no secrets and no privileged runner. Fork restrictions are useful but do not replace event design.

A replacement should run a repository-owned validator with pinned dependencies and a timeout. On a normal PR event, contributed validation code is still untrusted; isolate it accordingly and do not run it on a persistent privileged runner. Record the exact action commit after verifying it against the upstream release. Merge policy must actually require the check. YAML syntax validation does not prove any of these controls are effective.
