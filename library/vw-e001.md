# Find the large file without filling a disk

`VW-E001` · beginner · 35 minutes · free/local

## Mission

Simulation: a development worker reports growing storage use. Learn to inventory a directory without touching system logs.

## Outcomes

Distinguish apparent file size from allocated disk use; produce an evidence-backed cleanup proposal.

## Environment and scope

POSIX shell, `du`, `wc`, Python 3.9+. Work only in a new temporary directory; no sudo. A few kilobytes are sufficient.

## Prerequisite checks

Run `command -v python3` and `command -v du`. Understand absolute versus relative paths.

## Setup

```sh
lab=$(mktemp -d)
export lab
python3 - <<'PYCODE'
import os
from pathlib import Path
p = Path(os.environ['lab'])
(p/'app.log').write_text('request ok\n' * 100)
(p/'debug.log').write_text('debug detail\n' * 1000)
(p/'keep.txt').write_text('retention policy pending\n')
PYCODE
```

## Concepts

`wc -c` measures bytes in files; `du -k` reports allocated usage with platform-dependent rounding. A large file is a lead, not permission to delete it.

## Tasks

1. Run `du -k "$lab"/*` and `wc -c "$lab"/*`.
2. Identify the largest file under both measures.
3. Save a proposal outside the lab describing owner, retention and whether an open process might still hold a deleted file.

## Expected observations

`debug.log` has 13000 content bytes and should dominate this small fixture. Allocated sizes need not equal content sizes.

## Verification

Assert the measured byte count independently with Python. Explain why deleting a live log may not release space immediately.

## Troubleshooting

If glob expansion finds nothing, inspect `printf '%s\n' "$lab"` and rerun setup. Do not substitute a system path.

## Cleanup

After inspecting the path, remove only the three fixture files and then `rmdir "$lab"`.

## Reflection

Would rotation, retention reduction or growth prevention be the durable intervention?
