# Solution: Why DNS success does not prove HTTPS health

`VW-C002` · Solution and reasoning

## Explained answer

Resolution gives an address in a resolver context. It does not establish a route, TCP listener, trust chain, matching certificate name, negotiated TLS parameters or useful application response. For an authorised real target, `curl --connect-timeout 3 --max-time 8 --verbose https://HOST/health` provides staged evidence; redact credentials and headers before sharing.

A TCP timeout is compatible with filtering or path loss; it does not identify which. TLS hostname failure may indicate the wrong endpoint or certificate. HTTP 500 means an HTTP responder was reached, but a proxy may be that responder. SNI selects the TLS virtual host before HTTP Host routing. Accept recovery only with verification enabled and an expected response body. Do not use `-k` as a fix.
