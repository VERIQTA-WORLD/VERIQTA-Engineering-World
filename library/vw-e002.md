# Reject malformed release manifests

`VW-E002` · beginner · 45 minutes · draft · free/local

## Mission

Build a deterministic gate that rejects ambiguous release evidence before deployment.

## Outcomes

Validate data shape and return a useful failure without printing secrets.

## Environment and scope

Python 3.9+, standard library, no network. Use a disposable directory.

## Prerequisite checks

Confirm `python3 --version`; know dictionaries and exceptions.

## Setup

Create `valid.json` containing `{"service":"cart","replicas":2,"digest":"sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}`. Copy it to `invalid.json` and change replicas to `true`.

## Concepts

JSON validity is weaker than schema validity. Python booleans are integer subclasses, so a loose integer check can admit a dangerous value.

## Tasks

Write `validate.py FILE`: require exactly the three keys; nonempty string service; replicas an integer from 1 to 5 excluding booleans; digest `sha256:` followed by 64 lowercase hexadecimal characters. Exit 0 on success, 1 on invalid data and 2 on file/usage errors. Avoid printing document contents.

## Expected observations

The valid record passes; `true`, zero, six, unknown keys and truncated digests fail.

## Verification

Test each boundary plus missing file, malformed JSON, list input and null input. Save commands and exit codes.

## Troubleshooting

If `true` passes, inspect `type(value)` rather than trusting `isinstance(value, int)` alone.

## Cleanup

Remove only your disposable files after saving the test record.

## Reflection

What validation still belongs to a deployment platform? Optional: reject duplicate JSON keys.
