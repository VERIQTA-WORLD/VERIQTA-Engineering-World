# Day 1 solution: Define an engineering outcome

Draft guidance; not independent review.

## Reasoning and expected result

A defensible outcome might be “eligible search requests return a correct response within one second, measured over five minutes.” Define correctness and exclusions before measuring. Build status is evidence about the build gate only. Assign the team joint ownership of release feedback; avoid a handoff that treats users as someone else's problem.

## Acceptance

Your map contains five stages, a user-visible success definition, a measurement window and one stated uncertainty. Write a stop condition for a rollout if user results worsen.
