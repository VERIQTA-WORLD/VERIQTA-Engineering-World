# Solution: Choose a release gate for a small service

`VW-D001` · Solution and reasoning

## Suggested decision

Use isolated hosted PR jobs with read-only repository permissions, no deployment secrets and bounded runtimes. Execute required unit, integration and scan gates; separate parallel jobs can keep normal feedback under fifteen minutes, subject to queue time. Build and promote reviewed artifacts through a separate trusted workflow with a narrow environment boundary.

Ephemeral self-hosted runners can be appropriate when destroyed after each job with verified isolation, restricted networks and no inherited credentials; they add operational burden. The existing persistent privileged runner fails the stated threat model. Never expose it to fork code.

## Acceptance

A deliberately failing check blocks promotion. A fork cannot reach deployment authority. The deployment record identifies source, artifact digest and gate results. Advisory AI unavailability falls back to deterministic checks and human review, not silent automatic approval. This decision needs repository-specific enforcement testing.
