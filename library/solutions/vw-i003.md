# Solution: Replacement hidden inside a small Terraform diff

`VW-I003` · Solution and reasoning

## Evidence and conclusion

The recorded plan proposes replacement of a stateful resource. A rename may change an immutable provider field. Do not apply from this fixture. Require provider/version context, state mapping, data protection, restore timing and application dependency review.

## Plausible alternatives

Drift or an address refactor can also produce replacement-like plans. Compare config, state addresses and provider schema. A moved block can help an address refactor; it cannot make an immutable remote attribute mutable.

## Recovery verification

Use a fresh reviewed plan in the real workflow; test backup restoration and application reads/writes in an isolated environment. Explicitly define acceptable data loss and recovery time before approval.

## Prevention and trade-offs

Use policy checks to highlight destructive actions and peer review stateful changes. Prevent-destroy can block accidents but is not a backup and can complicate intentional lifecycle work.
