# Choose a release gate for a small service

`VW-D001` · intermediate · 40 minutes · free/local

## Scenario

Simulation: a six-person team releases a stateless API twice daily. Unit tests take two minutes, integration tests eight minutes, image scanning three minutes. A persistent self-hosted runner has deployment credentials. Fork contributions are expected. The team proposes running every PR on this runner to save cost.

## Constraints

No untrusted code may access deployment credentials. Feedback should usually arrive in fifteen minutes. Release images must be traceable to reviewed source. Assume sufficient hosted-runner quota; do not purchase capacity.

## Task

Compare hosted isolated PR jobs, ephemeral self-hosted runners and the existing persistent runner. Create a decision record with threat model, quality gates, artifact promotion and an exception policy. Describe a safe deterministic fallback if an optional AI review is unavailable.

## Verification

Trace a fork PR from event to merge to deployment. Identify the trust boundary, secret access point and approval owner. Include tests that reject intentional failures.

## Trade-offs

Explain cost, runner setup latency, cache trust and maintenance burden. Specify what new evidence would cause reconsideration.
