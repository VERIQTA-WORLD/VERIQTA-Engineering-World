# Solution: Build a release evidence bundle

`VW-P001` · Solution and reasoning

## Reference approach

Use `http.server` with a custom handler and an ephemeral local port in tests; test /health=200, /version matches the configured value and an unknown route=404. In tests, shut down the server in a finally block and join its thread. Hash a fixed allowlist of source files using hashlib, sorted by path. Record Git revision separately from uncommitted-state evidence; do not claim a revision represents dirty files.

## Validation design

Inject a failing assertion and verify the release script stops before acceptance. Revert the injected failure, rerun and compare hashes. Rollback is credible only when configuration and any data changes are compatible; this project intentionally has no database. A Dockerfile is an optional delivery artifact, not evidence of an executed container. A copied implementation should be credited and its limitations explained.
