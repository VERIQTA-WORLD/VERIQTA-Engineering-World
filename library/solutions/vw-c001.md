# Solution: A green deployment and a failed user request

`VW-C001` · Solution and reasoning

## Explained answers

1. The pipeline observation establishes that its configured checks reported success for R42. It does not show that the relevant user path was tested or that those tests had a correct oracle. Running processes show programs exist at the observation time, not that routing, dependencies or results are correct. Neither establishes complete checkout success.
2. Status success in the supplied gateway sample is 82/100 = 82%. These are requests, not unique people or completed transactions. Retries, failures before the gateway and unchecked bodies prevent converting the number into a customer-success claim. A 200 body could still describe a failed business action.
3. A possible definition is “among eligible checkout attempts observed at the agreed client or gateway boundary during a named five-minute window, return a verified successful checkout result within the agreed duration.” Define eligibility, result correctness, duration and retry policy before measuring. Report missing result checks as unknown rather than silently excluding them. The prompt does not supply a justified duration target; propose one for teaching and label the assumption.
4. Observation: 18/100 gateway requests returned 503. Hypothesis: R42 introduced a checkout-path problem. Decision: pause expansion under an agreed gate while comparing a controlled checkout input on known baseline/candidate revisions through the same path. If only the candidate fails repeatedly under comparable conditions, the release-specific explanation gains support; if both fail identically, a shared path or dependency remains plausible. Neither outcome alone identifies the exact failing component.
5. A release coordinator owns the next decision and observation log. An application owner checks result semantics; a platform/operations owner checks route and dependency evidence. They collaborate on the same user outcome while recording changes and avoiding concurrent uncontrolled mutations. The labels do not imply any one organisation must use these exact job titles.
6. A manual gate can enforce an evidence review or separate authority, but an uninformed approval adds delay without resolving uncertainty. A representative user-path check can expose a missed route or correctness failure, but its test data, environment and coverage can be inadequate. Both help only when their evidence and authority fit the risk and someone acts on failures.

## Reasoning and trade-offs

Pausing expansion can reduce further exposure without asserting a known cause. A rollback may be appropriate after checking prior artifact/configuration availability, data compatibility and a way to verify recovery. A passed rollback command is another output; the intended user result must still be observed.

Reject answers that infer a database outage solely from a 503, claim exactly 18 affected people, call 82% a long-term reliability measurement or use an extra approval as a substitute for a testable question.

## Self-assessment

You should have six supported answers, an explicitly scoped fraction, one controlled comparison with predictions and a decision whose limits are visible. If a check cannot falsify any hypothesis, refine it before proceeding to the release-packet exercise.
