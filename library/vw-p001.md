# Build a release evidence bundle

`VW-P001` · intermediate · 150 minutes · free/local

## Mission

Build a local release process that a reviewer can audit without access to your machine.

## Outcomes

Produce a container-ready application, deterministic tests and an explainable promotion record.

## Environment and scope

Python 3.9+, Git and shell. Optional Docker runtime; local only, no registry or cloud account. Allow two or three sessions.

## Prerequisite checks

Complete a beginner Python exercise and understand commits and image digests. Use a disposable repository, not this learning repository.

## Setup

Create a tiny standard-library HTTP service with `/health` and `/version`. Version comes from an explicit environment variable; never return environment contents. Initialise a local Git repository with a lab-only identity if needed.

## Architecture and constraints

Source → unit and HTTP checks → artifact manifest → review decision. Add Docker build as an optional branch. Bind local tests to 127.0.0.1 on an available port. Keep secrets out of fixtures.

## Milestones and tasks

1. Implement status and version endpoints and tests for unknown routes.
2. Add a script that stops on failed tests and records source revision and file SHA-256 hashes in JSON.
3. Document a candidate release decision and rollback to a previous source/config pair.
4. Optional: build a reviewed Dockerfile, record image ID/digest context and scan with an installed local tool; record exact versions and limitations.

## Concepts

An artifact hash proves identity of bytes, not safety or the correctness of the build environment. A build result and a release decision are distinct evidence.

## Expected observations

Changing a source byte changes its hash. An intentional failing test prevents the candidate evidence bundle from being marked accepted.

## Acceptance criteria and verification

A second run from the same inputs records the same source hashes. A deliberate test failure exits nonzero. HTTP checks verify response code and body; the server closes after tests. Optional container success is reported separately.

## Troubleshooting

Use an available local port; do not kill unrelated listeners. Exclude timestamps from deterministic identity comparisons. Do not hash the output manifest into itself.

## Cleanup

Stop your server, remove only your lab directory and optional lab images. Retain sanitised portfolio evidence elsewhere.

## Portfolio checklist

Include architecture, decisions, exact test commands, observed outputs, failure injection, rollback limits and independently authored versus referenced work. Explain the optional checks you did not run.
